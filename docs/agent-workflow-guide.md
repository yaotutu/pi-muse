# 开发 Agent 工作方式

本文面向在 Pi Muse 仓库工作的开发 Agent（当前主控为 Claude Code）。它约束开发过程，不是产品 Agent 的系统提示词，不改变 pi SDK、业务模型或实例规则。Claude Code 自动入口为各目录的 `CLAUDE.md`，项目约束在 `AGENTS.md`；架构、测试和文档分别由专项指南维护。

## 任务与执行（积极委派）

用户已于 2026-11-05 授权积极委派。主会话负责需求理解、产品/架构/契约/安全决策、派单、diff 审查、真实验收、跨端协调与本地提交；调查与实现优先交给执行者。委派不是强制的：小改动、快速查找、需要全局上下文的判断由主会话直接完成，不为委派而委派。

任务开始时确定目标、写集、非目标和验收，不为每次小修改创建任务文档。跨端任务先确定契约及失败语义，再修改对应调用方。根目录不属于 Git，两端提交分别检查；未提交文件不等于可覆盖的文件。

未实施方案留在 backlog/discussions，不能因为被记录就开始开发。历史分工、分支、端口、PID、测试数量与安装版本都是线索；重新核对当前仓库和进程，不把旧报告或记忆当成现状。涉及安全或授权且无法从当前请求判断时再询问用户。

## 执行者与模型路由

| 执行者 | 模型 | 适用与边界 |
| --- | --- | --- |
| 原生 sub agent（Agent 工具） | Claude 系（sonnet/opus/haiku/fable，不能指定第三方模型） | 服务端任务的默认执行者；也用于只读调查/探索、worktree 内实现、回归运行、独立复查与文档草稿。fork 可继承主会话上下文 |
| `codex exec`（外部执行者） | 由 codex 自身配置决定；本机实测为 `antigravity/gemini-3.8-flash`（magpie provider），不是 GPT，以每次运行头部输出的 `model:` 行为准 | 客户端 UI/视觉任务优先派发：需要看截图、比对布局的活（2026-11-05 实测通过，含读图、源码映射与新旧界面核对）。用法要点：任务书经 stdin 传入、`-C` 指定工作根、`-s workspace-write`、视觉任务用 `-i` 附图、可用 `--json` 取结构化输出；不使用 bypass 审批/沙箱的参数 |
| GLM / DeepSeek | 暂未接入（无 CLI、无 key） | 用户偏好用于服务端纯文字任务；配好 provider/key 后服务端切换为优先。接入前不得声称已由它们执行 |
| Gemini | 暂未接入（本机仅有 Antigravity IDE 配置，无 gemini CLI） | 用户偏好用于客户端视觉任务；配置后纳入客户端轮换 |

- 模型路由是用户偏好不是硬门槛：某执行者不可用或明显不适配时，主会话选择当前可用执行者并在交付中说明，不因此阻塞任务。
- 接入 GLM/DeepSeek/Gemini 的 key 与配置由用户完成；key 不写入仓库、规则或交付记录。
- 执行者不递归委派；并行任务用独立 worktree/分支隔离写集；执行者不做 commit、push、发布或修改版本，产物以工作区改动交回，主会话审查后统一提交。
- 外部执行者（codex 等）不读取真实实例数据、`.pi-muse/` 配置、凭据或密钥；派单时明确隔离数据目录与禁止事项。执行失败、限流或超时如实记录，不自动换模型重放。

## Claude Code 工具与上下文

- 文件读取/修改优先使用当前会话提供的专用工具，搜索、构建和 Git 使用可用工具；不要在项目规则里硬编码另一执行器的命令格式或内部工具协议。
- 优先读取当前模块源码、测试和契约，按任务加载指南；archive、截图目录、发布流水不默认整包加载。需要用户看图时用正文内嵌实际存在的图片，不只给路径。
- 使用本会话实际可用的浏览器、设备和视觉能力；工具缺失时如实报告，不沿用旧模型“无多模态”的永久假设，也不把未查看的截图描述成已视觉确认。
- 模型和工具由本会话环境提供，不自行切换模型、探测额度、改全局配置或用外部执行器绕过权限/限流。开发工具身份不决定产品业务模型。
- `.claude/settings*.json`、MCP 配置与用户级配置不是普通文档。不要为“适配 Claude”扩大权限或整体读取可能含凭据的文件；确需配置更改时使用相应配置入口并确认影响。

## 授权与失败

项目开发进程启停、真实模型调用费用和已验收模块的本地 commit 已有长期授权；执行前仍检查归属、隔离数据和实际影响。push、发布、版本写入、CI、签名、真实实例数据迁移与全局配置不在其中。

区分工具调用失败、业务执行失败与验收失败。模型限流、503 或工具不可用如实记录，不自动换模型或反复重放。写入结果未明先检查 diff/服务端状态，不直接重复提交。读取可安全重试时也不要形成无边界循环。

不整体输出环境变量、配置或日志；只查看定位所需的非敏感状态。真实 Key、token、用户会话与实例数据不进入报告或仓库，错误证据先脱敏。

## 验证与交付

| 变更 | 验证 |
| --- | --- |
| 服务端代码 | 对应回归与 `pnpm check`，按范围补真实模型、协议和页面验证 |
| 移动端代码 | lint/typecheck/test，当前真实后端/外部模型及相关 Android 原生链路 |
| 新业务功能 | 本地当前后端、外部模型、实际 `/docs` 渲染和 Android 验收；缺必要项标待验收 |
| 工程文档或规则 | 差异、引用、路径、命令与规则一致性；不启动业务或模型 |
| 用户手册/文档站 | 按[文档指南](agent-documentation-guide.md)做中英文同步、构建和适用浏览器检查 |

现有默认自动化含模拟模型/fixture，报告时写清本地门禁与真实验收的区别；通过数量不代表全部链路。文档整理不冒充业务复验，历史成功不替代本轮结果。

交付只需说明改了什么、运行了哪些检查、失败/未验项以及本地提交。收尾前审查工作区和暂存区 diff，只提交本次模块；不自动 push。根目录文件未被子仓库跟踪时明确说明，不宣称已版本化。

## 派单模板

委派实现类任务时，任务书至少包含以下字段（小任务可在同一段落紧凑表达），并随单传递隔离数据、真实模型要求与禁止事项：

```text
目标：用户可观察的变化
范围/所有权：允许修改的文件/模块、worktree 位置
非目标：本次明确不做的事
依据/依赖：契约、必读文档、已确定设计
约束：权限、数据、进程、发布、不可自动重试等边界
验收：可观察行为、异常与迟到场景、验证命令
交付：修改位置、实际验证结果、风险与未验证项
```

执行者交付后，主会话独立审查关键实现与实际命令结果，再执行真实验收；不以执行者结论代替验收。
