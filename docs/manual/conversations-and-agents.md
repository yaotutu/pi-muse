# 对话与会话

Pi Muse 只有一个助手，可以同时保留多条对话。消息页冷启动进入永久主聊天，你随时可以新建或切换会话。每条会话从自己的历史继续。

## 前提 {#prerequisites}

按[快速上手](getting-started.md#connect-mobile-client)连接匹配版本的服务端。聊天需要已配置可用外部模型。

## 会话边界 {#session-model}

从「消息」打开会话列表，可新建、切换、改名或删除会话。切换会话，或打开新闻与设置，都会保留各自的草稿和正在运行的对话。

主聊天不可删除，但可以重置。身份资料、长期记忆和工作区仍是实例全局内容；长期记忆按需检索，不每轮全量加载。

助手形象与紧凑的短状态一起悬浮在聊天内容区顶部中央，不单独占用一整行页头。人物保持透明，不放进大背景卡片；短状态直接显示当前运行、待审批或同步情况，完整内容也可由读屏读取。聊天内容开头留出相应起排空间，避免第一条消息与形象重叠，这段空间随消息滚动，不是固定页头。

点击形象或短状态，会围绕同一个形象的原位置展开当前会话的信息，而不是从底部弹出另一个面板；展开后是完整页面：形象仍在顶部中央且位置不变，页面直接是动态/审批/历史；关闭在右上角。历史按时间线展示全部登记活动，不提供状态筛选排。助手指令和技能统一在设置里管理。点击关闭或按 Android 返回键收起；系统开启减弱动效时直接切换显示。展开、收起和切换页面不会重建聊天或清空草稿，新闻与设置页不显示聊天上的悬浮形象。

## 本地记录与后台同步 {#local-history-and-sync}

Android 客户端在应用私有存储中保留近期已保存聊天的展示副本、输入框中的纯文本草稿和阅读位置。重新打开时先显示本地内容，再在后台核对服务端；没有变化时不重新替换消息列表。首次连接或没有本地副本时，仍需等待一次历史读取。这里描述当前源码能力，已安装 APK 需包含对应改动。

本地副本不是完整备份，也不是第二份服务端权威数据：每会话最多保留近期 200 条消息，最多 8 个会话的本地文档合计不超过 4 MiB；超长正文或工具内容会显示本机缓存截断提示。它不保存历史图片的完整载荷、附件草稿、正在生成的回复或未确认发送条目。离线时可以阅读已缓存内容和编辑文字草稿，但发送、消息反馈与审批仍须联网并完成相应状态核对；应用不会离线排队后自动发送。

正在阅读较早消息时，后台同步不强行跳到最新；点击回到最新、滚回底部或发送消息可恢复跟随。阅读位置以消息为锚点，若该消息已不在近期缓存或服务端历史中，会回退到可用内容。切换新闻或设置页仍保留当前聊天。

缓存按服务器与会话隔离，换服务器会清理旧本地业务数据。成功重置或同步发现服务端已更换聊天内部身份时，旧历史副本和对应阅读位置失效。缓存只负责先展示，不能使过期聊天版本获得发送或审批权限；网络恢复失败时保留可读内容并提示同步问题，不把缓存当作最新结果。

## 发送与停止对话 {#send-and-stop-conversations}

直接在「消息」输入文字，或按[附件说明](files-and-approvals.md#send-attachments)随该条消息提交图片/文本。模型回复以流式显示，工具与审批呈现实际执行事实。

每条会话同一时间只执行一轮。停止绑定本次运行，不影响后续轮次。断开聊天流、显式停止、超时或服务关闭会取消所属运行及子调用，未决审批作废；已有副作用不回滚。通知连接断开不等于停止聊天。

发送或写操作结果未明时，先同步权威历史/状态，不自动重发。切换页面不自动重发消息，不承诺应用进程终止后的继续执行。

## 消息反馈 {#message-feedback}

已保存的用户/助手消息可喜欢、不喜欢、撤销反应以及增删改评论；正在生成的消息和工具结果不可反馈。喜欢/不喜欢互斥，评论去首尾空白后 1–4000 字符。

反馈绑定公开会话、内部 pi 会话与消息 id，独立保存原始操作事件，不改变聊天版本、不触发模型或训练。重置后旧内部身份不能继续写反馈。写入超时或结果未明先回读确认，不自动重试。

## 助手指令与技能 {#session-rules-and-skills}

所有会话共享助手指令、技能开关、身份资料、长期记忆、工具权限和工作区。打开设置里的助手指令，点「编辑」，写完点「完成」，再点「保存指令」。最后一次成功保存从所有会话的下一轮起生效。指令上限 20,000 字符，保存空内容可清空。

助手指令或技能保存结果未明时，先点「核对服务器设置」，回读成功后再决定是否保存保留的草稿。

技能开关绑定技能的来源身份。目录与默认开关见[配置说明](configuration.md#skill-directories)。新闻和短信等后台领域继续使用各自的规则。

## 新闻与短信 {#background-services}

新闻和短信是以独立后台领域子 Agent 运行的全局服务，不注入主聊天技能，也不读取聊天历史或全局记忆；用户可在设置页编辑各自偏好，也可以在对话中直接用自然语言让助手调整对应领域规则。

- 新闻筛选与阅读见[新闻](news.md)。文章「讨论」直接将标记为不可信的引用追加到当前会话既有草稿，可编辑，不自动发送，也不弹出会话选择器；可返回原文章继续阅读。
- 短信是实例全局管线，首次默认关闭。后台分析重要短信后，系统通知直接写入主聊天历史，不额外启动一次主聊天模型回复；领域通知卡片默认不进入主聊天模型上下文，只有点击「引用到对话」显式引用发送后才进入当前轮。静默或失败不会制造通知。

短信采集依赖 Android 原生模块、系统权限、功能启用与应用进程存活；不承诺进程终止后采集或操作系统推送。导入/执行结果未明先核对条目和处理记录，不自动重发或重跑。

## 子代理 {#subagent}

助手可调用 `subagent` 完成一次受限的 single/parallel/chain 工作。它只有内存上下文、不创建会话或目录，使用相同工作区，结果返回父工具调用。它不能递归委派、排程、监控、登记独立活动或修改助手指令；角色只收窄权限。文件修改仍逐次人工审批，父停止会取消子执行。

## 重置与删除会话 {#reset-and-delete-sessions}

### 重置聊天历史 {#reset-current-session}

重置取消当前运行和审批，清空历史及反馈，并换一个内部聊天身份。公开会话 ID、共享设置、定时任务和网页监控均保留。结果未明时先回读会话状态。

### 删除会话 {#delete-session}

定时任务和网页监控的结果发到它们所属的会话。删除会话时先查看受影响的任务，再选择「一起删除」或「保留并转到主聊天」。转移会保留排期和运行记录，旧消息随会话删除。如果该会话还有定时任务正在运行，等这次运行结束后再转移。永久主聊天可以重置，始终可用。
