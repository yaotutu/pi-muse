# 定时任务、网页监控与执行记录

本页说明当前移动客户端中的定时任务、网页监控与执行记录入口。一级入口为「消息 / 新闻 / 设置」：在 main 聊天中创建任务或监控，再从「设置 → 记录与任务」进入「定时任务」或「网页监控」管理；当前会话执行过程可在回复顶部折叠条或执行详情中查看。内容按当前服务端与移动端源码核对，不等于某个已发布 APK 的实际界面。

## 用途与范围 {#purpose-and-scope}

- **定时任务**：到点后把任务内容作为一条用户消息投递到任务所属会话，触发真实模型执行。
- **网页监控**：服务端周期抓取一个公网 HTTP(S) 页面，在内容变化或关键词从未命中变为命中时通知来源会话。
- **执行记录**：每次执行由服务端自动记录的步骤时间线（工具调用、子代理、审批与文件落盘），无需模型显式“登记活动”。

聊天中的 `schedule` 与 `monitor` 工具只列出和控制当前会话记录，不接受跨会话目标。设置中的管理页使用服务端 REST 接口，不需要为了每次查看或管理都启动模型。当前没有底部「任务」汇总页，也没有专题会话选择入口。

## 前提 {#prerequisites}

- 手机已按[快速上手](getting-started.md#connect-mobile-client)连接真实服务端，并使用与当前源码匹配的 Android 客户端。
- 服务器需保持运行。默认每 30 秒扫描定时任务、每 60 秒扫描网页监控；服务停止期间过期的一次性任务不会补跑。
- 创建定时任务依赖当前会话的 `cron` 技能，创建网页监控依赖 `monitor` 技能；若被关闭，先在会话设置中恢复。
- 到点任务和监控检查都可能访问外部网络并产生模型费用。网页监控只访问公网 HTTP(S)，抓取内容是不可信数据。

## 查看执行记录 {#view-activity-history}

1. 对话中发生工具调用时，对应回复顶部会显示紧凑的过程条；点击可当场展开或收起该轮的步骤时间线。
2. 点击消息页顶部的助手形象，打开当前会话的详情页，包含「执行记录」与「审批」两个标签页。
3. 在「执行记录」中可查看进行中与历史执行，点击卡片展开各步骤详情（步骤经过脱敏，不包含内部推理、SQL 或原始文件正文）。
4. 若步骤关联待处理审批，可直接点击步骤进入审批详情（默认 24 小时审批窗口，批准后原任务原地继续）。
5. 有更多记录时自动或手动加载下一页。列表按创建时间从新到旧排列。

普通纯文本问答不产生步骤，因此不会额外占用消息列表视觉空间。

## 创建与控制定时任务 {#scheduled-jobs}

1. 打开「消息」进入 main 主聊天。任务归创建它的会话。重置聊天保留任务。
2. 在消息中说明任务内容与一次性或每日时间。例如：“创建每天 09:00 的定时任务，总结今天的待办”或“创建一次性任务，明天上海时间 09:00 提醒我复核清单”。
3. 等待模型实际调用 `schedule` 工具。成功结果应包含任务 ID 与下次执行时间；只有自然语言承诺不算已排期。
4. 进入「设置 → 记录与任务 → 定时任务」，点击「刷新任务」，再选择任务查看提示词、时间和事件。可编辑任务提示词，并按当前状态暂停、恢复、取消或重试失败任务；这些控制和删除均需确认。当前表单不提供时间编辑，也不能把调度控制当成停止正在运行的模型。
5. 也可在 main 聊天中让模型列出或取消当前会话任务。`schedule` 工具只有创建、列表、取消三类操作；暂停、恢复、重试和删除使用设置页，不要把 REST 管理能力当成模型工具能力。

一次性时间必须带明确时区。每日任务使用 `HH:mm`，按 `/api/health` 返回的服务端本地时区解释，而不是手机时区。暂停只停止后续调度；取消不是停止正在执行的聊天轮次；立即重试只用于失败任务，并会启动一次真实模型执行，不会自动重复提交。

## 创建与控制网页监控 {#web-monitors}

1. 打开「消息」进入 main 主聊天。监控通知投递到来源会话。
2. 在消息中提供公网 HTTP(S) 链接、触发条件和检查间隔，最短 5 分钟。例如：“监控 `https://example.com/product`，出现‘补货’就通知我，每 5 分钟检查一次。”
3. 触发条件只有两种：`change` 表示内容指纹变化；`contains` 表示指定关键词从未命中变为命中，必须提供关键词。
4. 等待模型实际调用 `monitor` 工具，再通过工具列表结果核对条件、间隔、累计检查和错误。进入「设置 → 记录与任务 → 网页监控」可刷新列表，查看标题、状态和网址，按当前状态暂停、恢复或停止，并在确认后删除；当前页面不提供逐次检查历史或条件编辑表单。
5. main 聊天中的 `monitor` 工具也可列出、暂停、恢复和停止当前会话的监控，但没有删除操作。停止是终态，不能恢复；要继续监控需重新创建。

`change` 的首次检查只建立基线，不通知；之后内容指纹变化才通知。`contains` 持续命中不会重复通知，只有未命中转命中才通知。暂停或停止只控制后续检查，不会立即发起一次检查，也不会删除已经观察到的事实。

## 可见结果 {#visible-results}

- 定时任务到期后，来源会话聊天会出现以「⏰ [定时任务]」开头的用户消息并进入真实模型执行。
- 网页监控命中后，来源会话会收到以「📡 [监控]」开头的通知。
- 执行状态与步骤随真实执行自动更新；失败、拒绝、取消、过期和中断会保留，不会伪装成成功。

默认扫描周期意味着实际执行可能稍晚。若工具结果显示结果未明，先重新读取当前状态，不要自动重发写操作。

## 限制与排错 {#limits-and-troubleshooting}

| 现象 | 检查 | 处理 |
| --- | --- | --- |
| 任务没有到点执行 | 服务器是否常开、来源会话是否正在运行、扫描是否稍晚 | 等待下一轮扫描；正在运行的会话会让到期任务等待。停机错过的一次性任务不会补跑。 |
| 重启后一次性任务没有执行 | 任务是否已过期 | 到期任务不会补跑；需要时新建。每日任务会重算下一次未来时间。 |
| 任务失败 | 最近执行结果和错误状态 | 失败不会自动重跑；核对影响后在设置的定时任务页手动重试，或按需要新建。 |
| 每日时间不符合预期 | `/api/health` 返回的服务端时区 | 按服务端时区填写 `HH:mm`，不要按手机时区换算。 |
| 监控不通知 | 条件、最近检查、抓取错误和服务状态 | `change` 首检和未变化不通知；`contains` 持续命中不重复通知。 |
| 监控抓取失败 | URL 是否为公网 HTTP(S)、页面是否可访问、Web 工具是否启用 | 修正链接或稍后重试；失败状态保留到下一次成功检查。 |
| 找不到旧任务汇总页 | 一级入口为消息、新闻、设置 | 在「设置 → 记录与任务」管理任务和监控；执行历史在聊天详情面板的「执行记录」页。 |
| 操作结果未明 | 工具结果和当前会话回读状态 | 先核对记录是否仍存在及当前状态，再决定是否重试；不自动重发。 |

删除专题会话时，确认页列出所属任务和监控。可以一并删除，也可以保留并转到主会话。保留会延续原任务的排期、启停状态及最近结果，未投递的监控通知也随之转移。若定时任务已在原会话执行，先等它结束，再选择保留。重置主聊天只清空会话历史，保留任务和监控。
