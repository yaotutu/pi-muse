# 新闻阅读

新闻也是完整智能体，拥有独立私聊与阅读页面。点击顶部新闻头像默认进入阅读主视图；长按头像进入「智能体设置」，在「主视图」选择「阅读」或「对话」。选择按服务器与智能体保存在本机，不改变指令、记忆或会话。阅读页没有输入框或底部导航，列表与聊天共用顶部头像栏，文章详情隐藏头像栏以便阅读；左右快速横扫列表或文章可切换相邻智能体，到两端不循环，反馈操作行与横向内容不参与。切头像或往返设置后保留当前文章和阅读位置；Android 返回先关闭文章或来源，再从阅读根回「全部」。服务端复用既有信息处理与模型能力，不另建推荐引擎。

## 阅读与筛选 {#reading}

- 阅读列表与头像栏以细分隔线分层，不逐篇堆叠卡片；每篇显示来源、中文时间、标题和最多两行摘要。顶部菜单选择「推荐／全部」，收藏单独筛选，来源与手动抓取在「更多」中；默认显示推荐。抓取时间、分析进度与失败数量在「RSS 来源」中查看。
- 「推荐」只显示模型已完成结构化筛选并明确选中的文章，推荐理由在详情中展示；模型没有选中的文章仍可在「全部」中阅读。
- 「全部」按发布时间从新到旧排列；发布时间无效时使用服务端首次接纳时间。收藏筛选只过滤列表，不改变排序。
- 点按文章进入整页详情，阅读服务端清理后的安全文本和推荐理由，正文支持文字选择。详情顶栏只保留返回，不提供原文外链或更多菜单；反馈与讨论固定在底部，不随正文滚动。外部标题和正文仍属于不可信内容。
- 服务重启后，已接纳文章、推荐结果、反馈和收藏仍从服务端恢复。

## 带到会话讨论 {#discuss-in-chat}

在文章详情的底部操作栏点击「讨论」。服务端读取原文并写入新闻绑定智能体的当前会话，成功后客户端切到该智能体；不会自动调用模型或替你发送问题。消息显示「来自新闻」，可以继续提问、讨论，或明确要求将反应/评论保存回新闻功能。阅读本身不会把每篇文章推送到聊天。

承接智能体默认主智能体，在新闻智能体设置页→「新闻设置」中查看或更换；RSS 与新闻偏好也归新闻功能，不跟随当前选中聊天。讨论提交超时或断线时不要重复点击，先进入承接会话核对，再返回文章点击「已核对，恢复操作」并确认；会话读取成功后才解除锁定，不会重发上一次讨论。智能体重置不改变绑定，后续讨论使用该智能体的新会话。

## 管理 RSS 源 {#sources}

1. 打开新闻阅读列表顶部的「更多」→「来源与状态」，或从新闻设置进入「RSS 来源管理」。页面默认先显示已有订阅，再显示抓取与分析状态；顶栏返回原入口。点击「添加来源」展开表单，填写 RSS2 源的公网 HTTP(S) 地址及可选标题。
2. 在添加表单中展开「推荐中文来源」，选择「填入」，表单会填入相应地址和标题；核对后点击「添加来源」才会提交。也可手动输入。例如少数派、36氪、机器之心和 IT之家；可用性取决于来源网站。当前只支持 RSS2，不支持 Atom。
3. 收起表单或离页不清空当前连接内的输入；再次展开可继续编辑。添加结果未明时表单保持可见，必须回读核对并显式解锁，不会重复发送。添加时服务端会实际抓取并校验 XML；带用户名或密码的 URL 会被拒绝。
4. 来源页显示抓取时间、等待分析和分析失败数量；源列表显示各源最近抓取时间与受控错误。某个源损坏或暂时不可用时，其他源和已读文章仍可使用。
5. 删除源只停止后续采集；已经接纳的文章、评论、喜欢/不喜欢和收藏不会被删除。

服务端默认每 30 分钟采集一次；后台采集只抓取新条目，不会自动重排已知失败的文章。手动刷新先完成 RSS 抓取并返回新增数量，文章分析在后台继续；刷新不会等待模型整轮结束，也不会自动重复提交未明结果。条目缺少标题或可读正文时，整个源会记录受控解析错误，而不是静默当作空源。

## 反馈与推荐 {#feedback}

- 每篇文章直接显示「喜欢」「不喜欢」「收藏」；列表行和详情底部的操作整组靠右，窄屏允许换行，不必长按打开菜单。
- 喜欢与不喜欢互斥，再次选择已选反应可撤销；收藏独立于喜欢/不喜欢，再次点击可取消。不喜欢不会立即移走当前条目。
- 选中状态通过图标、文字和主题底色区分；同一篇文章写入时暂时禁用其他反馈，结果未明须回读核对后显式解锁，不自动重发。
- 阅读页不再展示评论列表、评论输入或评论徽标；服务端已有历史评论仍保留，不因界面调整而删除。
- 反馈不会立即触发模型。下一次后台分析会读取近期文章、反馈、评论和收藏作为局部证据；收藏是较弱信号。
- 「明确偏好」由用户保存；「模型推断」是服务端从反馈更新的摘要。两者分开保存，推断摘要不会覆盖明确偏好、智能体规则或全局用户资料。
- 新建新闻智能体的默认规则要求推荐理由和模型推断摘要使用简洁的简体中文；RSS 标题和正文保留原文，不自动翻译。

从新闻智能体设置页→「新闻设置」的「新闻偏好」保存明确备注；「RSS 来源管理」进入订阅管理。从设置进入 RSS 后，返回会逐层回到新闻设置、智能体设置页，再回实际来源的聊天、新闻阅读、通知讨论或智能体管理，不会跳到其他来源。

未保存的偏好草稿只保留在当前连接内存中。切到 RSS、其他成员或聊天再返回，以及应用从后台回到前台，都会保留输入；重新打开或前台核对时，只有未修改的备注才跟随服务端更新。读取失败保留草稿和上次读取的偏好。「刷新核对」也不覆盖未保存输入；保存结果未明时，离页重开不会解除锁定，须显式核对后才能再次保存，不会自动重发。点击「保存偏好」才提交明确备注，留空保存表示清空；换连接或重启应用不会恢复未保存草稿。

## 刷新与失败 {#refresh}

- 阅读列表顶部「更多」中的「抓取新文章」发起一次抓取；列表读取失败时另显示「重试列表」，只回读列表和状态，不重新抓取。手动抓取已运行时返回冲突，不会排队或并发抓取。
- 抓取写入结果未明时，先回读状态并核对，再明确解锁；客户端不会自动重发。
- 采集失败会在新闻状态或源列表显示受控错误，不会把坏源静默当成空源。
- 模型分析失败时，全部时间线仍可读；推荐视图只显示已经确认成功的结果。
- 再次手动刷新可以重新排队已知失败的文章；正在运行的批次不会被重排。
- 新闻页只在前台且状态显示处理中时短时回读状态和列表，终态后停止；新闻不使用新的 SSE 或全局轮询。

## 边界 {#boundaries}

新闻不做全文网页抓取、搜索、向量推荐、系统通知或 OPML。聊天中的 `feature` 工具只沿已有可验证来源查询与记录反馈，不提供任意功能数据浏览。新闻以成员身份提供私聊、文件和规则入口；同样可作为通知承接方、配置技能与 Dream；内置智能体不能删除。私聊不自动启用 RSS 后台。
