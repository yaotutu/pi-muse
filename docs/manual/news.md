# 新闻阅读

新闻是实例全局 RSS 采集与推荐服务，不是独立聊天身份。阅读、源与文章反馈不随主聊天重置。本文对应当前源码，实际入口需核对安装版本。

## 阅读与筛选 {#reading}

新闻页展示全部文章或成功模型推荐，并可筛选收藏。按发布时间与稳定 id 倒序排列；无有效发布时间使用接纳时间。分页游标随筛选绑定，改变条件从第一页重新读取。

文章详情显示服务端清理后的纯文本、来源和推荐理由。标题、正文和链接属于不可信外部内容，不是权限或用户指令。模型失败不产生假推荐，全部文章仍可读取。

## 带到会话讨论 {#discuss-in-chat}

点击文章「讨论」直接回到「消息」主聊天，将标记为不可信的文章引用追加到已有草稿。引用可编辑，不会自动发送，也不弹出会话选择器；可返回原文章继续阅读。不创建新闻私聊或独立讨论，阅读本身不会启动聊天或把所有文章注入主聊天。

发送结果未明先同步当前会话历史，不反复发送引用。文章反馈不是执行指令；需要助手采取行动时在会话中明确请求。

## 管理 RSS 源 {#sources}

添加 RSS2 公网 HTTP(S) 源及可选标题。添加时真实抓取并验证 XML，不接受带用户名/密码的地址；不支持 Atom。服务保留 DNS、SSRF、固定 IP、逐跳重定向、大小、深度、条数、超时和取消边界。最终 HTTP 响应必须成功；DTD/实体声明、损坏 XML 或缺少源标题会产生受控错误，不静默当空源。

缺少文章标题或稳定标识（guid 或有效原文链接）的条目会跳过；超过一半条目无效时，整个源本次解析失败。有标题和稳定标识但正文为空的条目仍保留，以标题作为最小正文；这不代表已抓取全文。添加源只验证，不立即接纳文章，并返回本次跳过的条目数。

源地址去除 fragment、统一协议与主机大小写并去除默认端口后查重；重复时错误文案包含已有源 ID，不按重定向的最终地址合并。抓取/解析失败提供受控分类，区分网络、私网阻断、超时、HTTP 状态和解析问题；源列表保留错误文案及可选分类，旧错误不推断补齐。具体字段以服务端自动接口文档为准。

默认每 30 分钟采集。单源失败不阻止其他源；删除源只停止后续采集，保留已接纳文章、反馈和收藏。添加/删除结果未明先回读源列表，不自动重发。

## 反馈与推荐 {#feedback}

文章喜欢/不喜欢互斥且可撤销；收藏独立；服务端支持有界评论。反馈事件写入通用习惯热缓冲：未归纳前作为近期示例进入下一批新闻筛选（收藏是弱信号），达到 5 篇不同文章反馈或每 2 小时周期到达时，由通用习惯归纳引擎提炼为持久行为习惯，不把单次孤立反应硬写进你的显式指令。

明确偏好保存在工作区的 `subagents/news/INSTRUCTIONS.md`（请求/响应字段均为 `instructions`，支持通过[顶部 Frontmatter `include:`](instructions.md#frontmatter-include)引用其他工作区纯文本），不影响主聊天 `INSTRUCTIONS.md` 或全局资料。可以在「设置 → 新闻偏好」整份保存（最后成功保存生效），也可以在工作区文件中编辑同一份原文，或在聊天中请助手通过 `subagent` 提出修改并审批。通用习惯引擎沉淀的行为习惯（`habits`）可在新闻偏好或习惯管理接口（`/api/habits/news`）查看、手动增删改及手动触发归纳，绝不覆盖明确偏好、助手指令或 USER。

推荐理由和归纳后的行为习惯默认简体中文，RSS 标题与正文保留原文。写入结果未明先回读，不自动重发；客户端草稿行为依适配版本核对。

## 刷新与失败 {#refresh}

手动刷新同步完成抓取并返回新增、跳过数量，不等待后台模型完成。同一时刻只允许一次抓取。定时抓取不重排已失败文章；明确手动刷新可在非运行批次重排失败项。新闻模型轮仍在运行时，刷新结果的 `resetDeferred` 为 `true`，失败项保持原样，批次结束后不会自动补重试；为 `false` 也不代表模型分析完成。模型失败不自动重试。

单个或全部源抓取失败时，刷新仍可返回成功响应，因此不能只凭 HTTP 成功判断源健康；请读取源列表的错误及分类。接口调用须发送有效 JSON 空对象 `{}`，空请求体、损坏 JSON 或额外字段会被拒绝，不执行抓取或失败项重置。

未知抓取结果先读取状态、来源和文章；列表读取失败只重读列表，不应自动再发抓取。受控错误不包含原始凭据或内部诊断。

## 数据保存 {#storage}

新闻源、文章、点赞/不喜欢、收藏、评论、分析批次与推荐结果统一保存在服务端独立的 `news.sqlite`（已筛选且无用户反馈的历史文章有界保留最多 2,000 篇，带喜欢/不喜欢、收藏或评论的文章永不裁剪），不再运行时重写整份新闻 JSON；定时任务、目标、审批、短信、Dream 与通用用户习惯（`habits` 与反馈热缓冲）保存在默认业务库 `main.sqlite`。聊天历史仍由 pi JSONL 管理，不随新闻存储调整而改变。

服务端新闻接口与 Agent 的[数据库工具](database.md)使用同一份新闻数据。Agent 可以自主查询、修改、扩展结构或删除表，没有逐次 SQL 审批；直接破坏内置表结构可能导致新闻功能不可用，系统不会静默重建为空库。数据库操作也不会自动重算历史推荐或重跑模型。



## 边界 {#boundaries}

新闻维护独立的筛选规则与习惯记录，不修改主聊天指令；同时不提供独立工作区、聊天会话、Dream 或系统通知投递绑定。新闻推荐不写聊天系统通知，也不额外增加全局轮询/通知流。工作区、会话工具与人工审批规则不会因文章讨论而改变。
