# 专职子代理（Subagents）

Pi Muse 只有一个负责日常对话的主助手，但在主助手背后，系统按具体业务封装了一组**专职子代理（Subagents）**。它们各自拥有独立的提示词、工具与规则，既可以由后台定时/事件自动触发，也可以在聊天中由主助手按需自动派活。

## 当前内置的 4 个专职子代理 {#builtin-subagents}

| 名称 | ID | 触发方式 | 负责什么 |
| --- | --- | --- | --- |
| **短信助手** | `sms` | 主聊天路由 + 后台触发 | 过滤手机短信（默认静默，只提醒取件码、账单、行程、安全验证等重要消息）、归档汇总简报，以及在聊天中查短信和修改 `subagents/sms/AGENTS.md` 规则 |
| **浏览器助手** | `browser` | 主聊天路由 | 在独立上下文中操作共享真实 Chrome 执行多步网页浏览、交互与信息提取，遇登录墙或验证码发起 `/browser` 人工接管 |
| **习惯归纳助手** | `habits` | 仅后台触发 | 定期从你对短信的点赞/点踩/收藏/评论反馈中提炼长期行为习惯 |
| **记忆整理助手** | `dream` | 仅后台触发 | 后台定期整理主会话增量消息，提炼长期记忆与用户画像变更提案供你确认 |

## 它们是如何工作的 {#how-they-work}

- **无跨次聊天历史（纯函数执行）**：每个专职子代理每次被调用时都在一个干净的独立内存会话中运行，不继承主聊天历史，也不会在工作区建多余的会话目录；运行结束后只把精炼结果交回主助手或落入对应业务库。
- **自动路由，无需手动切换**：在主聊天框里直接用自然语言提问即可（例如“帮我查昨天的快递取件码”“打开这个网页帮我查一下内容”），主助手会根据各子代理声明的能力自动派发任务。
- **规则修改仍须人工审批**：当你在聊天中要求修改短信偏好规则时，对应的专职子代理会先读取现有规则合并，再弹出完整差异卡片等待你手动批准后才写入。

## 后台结果去向与聊天可见性 {#output-and-visibility}

不同业务按自身特点决定输出去向：
- **独立页面浏览**：完整原始短信列表保留在专属页面，不会刷屏主聊天窗口；你想针对某条短信展开讨论时，再主动带入主聊天。
- **主聊天窗口提醒**：例如筛选出的重要短信提醒和归档总览简报会直接发到主聊天窗口；**凡是进入主聊天窗口的通知消息，主助手都直接可见**，你可以直接在下面接着提问或调整规则。

## 查看与管理专职子代理 {#inspect-subagents}

服务端通过 `GET /api/subagents`、`GET /api/subagents/:id`、`PATCH /api/subagents/:id` 与 `GET/PUT /api/subagents/:id/mcp` 向客户端统一暴露全部已注册 Subagent 的状态与配置，包括：
- 身份信息、触发入口（`chat` / `background`）、统一启用开关（`PATCH /api/subagents/:id` 同时控制对话路由与后台自动调度；`sms` 默为关闭，启用手机短信同步或收到短信上传时自动开启）与路由说明（`routingHint`）
- 绑定的内置系统提示词全文、工具清单、技能与按需选用的 MCP 列表
- 关联的用户规则文件（`AGENTS.md`）原文、`include:` 诊断及已归纳习惯快照

如需修改短信的明确规则，可直接在设置页、工作区文件页（`subagents/sms/AGENTS.md`）编辑，或在聊天中直接告诉助手提出修改并审批。
