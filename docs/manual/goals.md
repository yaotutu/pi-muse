# 长期目标

本页说明长期目标的概念、通过聊天管理目标的方式，以及目标进入模型上下文的规则。内容按当前服务端与移动端源码核对；源码核对不等于本轮实际业务运行或发布 APK 实测，已安装 Release 的可用功能以该版本界面和发布说明为准。

## 用途与范围 {#purpose-and-scope}

长期目标是全局记录，不属于任何智能体。进行中的目标不会预先注入提示；当智能体的 `goal` 技能开启时，模型按需通过 `goal` 工具查询全局目标，用于规划和回答目标相关问题。

目标本身不执行计划、不创建定时任务、不监控网页，也不会自动调用工具。需要实际执行时，仍在聊天中明确委托模型，或按[定时任务、网页监控与活动历史](tasks-and-monitors.md)单独创建任务与监控。

## 前提 {#prerequisites}

- 手机已按[快速上手](getting-started.md#connect-mobile-client)连接真实服务端。
- 当前移动端没有独立的目标管理入口：一级导航仅「消息 / 新闻 / 设置」，没有目标页面，也没有把目标管理挪入设置。既有目标数据和服务端目标能力保留，不会因导航调整被删除。
- 若希望通过聊天让模型创建、列出、勾选或改目标状态，当前智能体的 `goal` 技能需保持开启；默认内置技能开启。

## 通过聊天管理目标 {#manage-goals-in-chat}

1. 在任意智能体的私聊或群聊中，明确要求模型执行目标操作，例如「新建一个目标：每周整理一次收件箱，包含两个里程碑」或「把目标××改成已暂停」。
2. 模型通过 `goal` 工具执行，结果以工具回执为准；模型口头答应不等于创建或修改成功，可在后续对话中要求重新列出目标核对。
3. 目标是全局记录，在任何智能体中创建或修改都对所有智能体生效；换智能体聊天不会丢失或复制目标。

通过聊天使用 `goal` 工具属于模型执行，会产生模型调用费用。写入结果未明时，先要求回读列表核对，再决定是否重新发起，不要连续重复同一条指令。

## 可见结果 {#visible-results}

- 新建目标保存为全局目标，初始状态是「进行中」。
- 「进行中」目标可通过 `goal` 工具按需查询，供所有智能体参考；暂停、完成或归档后不再作为活动目标提供。
- 里程碑勾选会改变下次查询时返回的进度和下一个未完成里程碑。
- 把目标设为「已完成」会自动勾选全部未完成里程碑；所有里程碑都勾选也不会自动完成目标，完成目标必须显式更改状态。

## 限制与排错 {#limits-and-troubleshooting}

| 现象 | 检查 | 处理 |
| --- | --- | --- |
| 找不到目标管理页面 | 当前客户端导航 | 当前移动端没有独立目标管理入口，这是预期行为；既有目标数据和服务端能力保留。 |
| 目标没有影响回答 | 目标是否为「进行中」 | 只有进行中目标作为活动目标供 `goal` 工具查询；完成或归档后不再提供。 |
| 想修改目标详情 | 是否已有目标 | 当前源码不能编辑已有目标的标题、描述、分类或里程碑文字，也不能新增、删除单个里程碑。先创建核对后的新目标，再按实际可用入口处理旧目标。 |
| 勾完里程碑但目标未完成 | 目标状态 | 里程碑不会自动完成目标；显式把状态改为「已完成」。 |
| 模型说已创建但没有生效 | 工具回执与回读结果 | 以服务端回读的目标列表为准；结果未明时先核对，不自动重发指令。 |
| 换智能体后目标仍可见 | 目标是否全局 | 这是预期行为；全局目标会作用于所有智能体，删除智能体不会删除目标。 |
