# 单主助手与多会话的设计决策

本文记录本次重构的产品边界与取舍，不是另一份接口规范，也不证明部署或验收状态。
当前实现以[架构指南](../architecture.md)及源码为准；HTTP/SSE 以
`src/http/contracts/` 和匹配版本实例的 `/docs`、`/openapi.json` 为唯一事实来源。

## 为什么移除多助手模型

移动客户端优先、个人自用，不需要让用户管理多个独立身份、工作区、权限、转发路径或讨论树。
因此选择一个助手身份，按话题拆分上下文；不保留群路由、成员管理、跨助手通信或旧接口别名。

本次是用户明确授权的 clean break：不迁移旧历史，不维护兼容分支。
清理旧实例业务数据是显式部署操作，不写成启动时自动删除或转换；配置、凭据、签名与浏览器登录资料不属于历史清理目标。

## 会话而非助手

- `main` 是永久默认会话，不能删除，可以重置。
- 专题会话按需创建、改名、重置、删除；它们不是新的助手身份。
- 公开 `sessionId` 在重置后不变；pi 的 `piSessionId` 随历史上下文重建而变化，不能混用。
- 每个会话的 `INSTRUCTIONS.md` 只注入本会话，不自动继承默认会话指令。
  后台管线可以显式读取默认会话规则作为偏好，但不能借此给所有专题会话增加规则。
- pi SessionManager/JSONL 仍是聊天正文、附件与工具事实的唯一权威；会话目录只保存元数据。

## 只有一个文件工作区

所有会话与子任务使用同一个 `DATA_DIR/workspace/`。没有助手私有目录，也没有 `shared/` 别名。
会话上下文分开，不代表文件隔离；删除会话不能删除共用文件。

文件路径继续拒绝绝对路径、父目录穿越和符号链接绕过。模型 write/edit 必须展示完整修改前后内容，
逐次人工审批并绑定文件版本。审批回到发起的 `sessionId/runId`；工作区本身没有另一个 owner。
拒绝、过期、文件变化或取消后，不得凭旧审批提交。

## 子任务不持有业务身份

`subagent` 只在父轮工具调用中使用独立内存上下文，返回结果，不创建独立历史、会话目录或文件根。
它不是另一个可被用户选择的助手，也没有独立持久权限模型。

子任务从父 SDK 当前实际工具快照继承能力，固定去掉递归委派、排程、监控、活动管理与会话指令修改入口；
角色定义只可收窄，扩展不能扩权。文件或技能修改仍归父轮审批与取消约束。
这里的“纯函数”指不持有跨调用业务状态，不是声称显式批准的工具操作没有副作用。
运行观察、父历史中的工具结果与受保护诊断 trace 不构成子任务独立会话。

## 新闻与短信是后台管线

- 新闻持有全局来源、文章与偏好。推荐只产出推荐决策，不承担聊天身份，也不生成通知。
- 移动端讨论新闻直接在默认主聊天输入框加入标记为不可信的引用，追加到既有草稿，不自动发送。
- 短信是全局管线。重要结果通过正常通知追加入口写入 `main` 的 pi 历史，不投递专题会话，
  也不为通知本身再启动一次主助手模型轮。
- Dream 使用全局整理状态，保留建议来源会话引用；来源已删除时不得重建它。

## 移动交互

一级入口固定为消息、新闻、设置。移动端当前只开放 main：消息本身就是可直接输入的主聊天根页，
不经过目录或会话选择；专题的新建、切换、改名和删除入口暂缓，不删除服务端既有数据。
形象只作展示，操作入口保留主聊天的重置、指令、技能、执行和审批；文章及设置子页无底栏。
新闻讨论直接带到主聊天并可返回原文章；正常消息根页保留一级底栏，键盘和覆盖层可隐藏它。
未明写入保留原稿并先核对；自动刷新不能当作用户确认，更不能自动重发。

## 不扩大本次工程边界

继续使用 pi SDK 的执行循环、函数式工厂、显式依赖注入与文件仓储。
不引入第二套模型循环、多用户架构、事件总线或数据迁移框架。
产品模型不获得 shell；模型凭据不进入客户端、日志或历史；外部内容与网络请求保留原安全边界。

代码门禁、真实模型、实际 `/docs` 渲染、Android 原生链路和共享实例升级分别验收；
实现、测试通过、本地提交与发布不混为一谈。具体命令和验收边界见[测试规范](../testing.md)。
