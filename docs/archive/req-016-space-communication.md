# REQ-016 空间双向通信首批验收

日期：2026-11-02。状态：通信底座和现有聊天工具入口已验收，专用交互 UI 待实施。本文是本次证据记录；当前协议与生命周期以契约源码和架构规范为准。

## 本批范围

- 普通空间、新闻和短信空间默认互信，可以双向请求；不增加空间白名单、绑定授权、逐次调用确认或仅 main 可调用的限制。已有鉴权、凭据保护、安全文件根与模型文件修改人工审批保留。
- 新增 `space` 工具及共用服务的发现、请求、讨论历史 HTTP 入口。目标在自己的独立 pi 讨论中使用自己的规则、技能、数据和工作区，不复制双方主聊天历史；必要背景由发起方显式传入。
- 结果沿原调用返回，不依赖来源会话的通知队列，也不额外唤醒来源模型。默认通知绑定只决定后台主动消息落点，不限制谁能调用、也不改变请求回复地址。
- 追问保留同一讨论，回复可以是澄清问题。原始正文与工具事实只存目标空间的 pi JSONL，不另建聊天数据库或可靠消息队列，不重试结果未明的操作。
- Stop、调用断开、超时、来源或目标 reset/delete、服务关闭取消关联执行。目标重置清理自己的讨论；来源重置不删除另一空间已有讨论，不向新来源会话投递旧回复。
- 跨空间文件审批归原调用者，文件预览和实际写入仍属于目标空间；后续嵌套请求沿用审批归属。技能开关查询始终使用处理空间，不能因审批回到发起方而查询其技能配置。

## 验收结果

- 服务端 `pnpm check` 最终通过：类型检查、675 项单元/集成、39 项 E2E、服务端构建、Web 生产构建和差异检查。此门禁保留既有 fake-provider 测试，不把它称为真实模型证据。
- `tests/live/space-communication.ts` 最终 16/16，通过隔离真实 HTTP 后端实际请求外部模型 28 次，无模型替身或自动重试。核对目标信息工具、主聊天不混入、连续追问、反向与普通空间互调、目标回调来源不死锁、改绑不改变回复地址、真实主模型工具调用、文件审批拒绝不写入、目标技能开关、重启恢复、BUSY 和取消/删除不复活。
- Android API 36 的隔离原生应用连接当前源码后端，在聊天实际发送短信查询；主模型调用 `space request`，目标实际调用 `information`，结果带回合成取件码。继续使用同一 discussionId 追问成功，目标 pi 历史独立保留三轮（含先前 Web 发起的一轮）。实际展开通用工具卡，显示 `space` 名称；强制停止并重开应用后，原生页面和服务端历史均保留本次追问与结果。
- 当前 `/docs` 经真实 Chrome 渲染，空间通信分组、请求端点、上下文/取消/审批语义可见，无页面脚本错误。Web DEV 实测真实工具返回、刷新历史和不存在目标的失败卡，不以 OpenAPI JSON 代替页面验收。
- 中英文会话与空间手册同步，`pnpm docs:build` 和差异检查通过。移动端源码没有变化，不重复移动端 lint/typecheck/test 或重建 APK；原生兼容性以实际已安装隔离应用和当前 Metro 加载源码验证，不宣称新客户端版本发布。

## 首次失败与修正

- 第一轮真实场景为 12/13，关闭用例在 HTTP socket 的 close 事件到达前立即断言；最终证据表明连接实际已关闭。仅把验收驱动改为有界等待后复跑，后续增加回调、审批和目标技能验证，最终 16/16；不放宽产品取消语义。
- 首次完整门禁出现旧工具目录断言、记忆场景误取压缩请求、测试运行中移动文件的旧路径失败，以及既有 Chrome 用例超时。同步新增工具断言、显式设置普通协议夹具上下文窗口（压缩专项仍单独覆盖），重置路由测试改为真实 HTTP。使用本机 Node 24 重跑完整门禁通过，Chrome 用例本次也通过；未修改浏览器业务实现或放宽超时。
- 原生驱动曾误点隐藏树、在无软键盘时用 Back 关闭连接表单，以及误填隔离登录值；按实际前景和软键盘状态重新操作、通过界面测试连接后完成验收。Scalar 初次驱动未展开折叠分组，修正定位后实际渲染通过。这些是验收操作失败，不宣称首次脚本全部通过。
- 内置 Browser 插件初始化因其运行时版本路径不匹配而失败；没有改动全局插件配置，页面证据由本地 Playwright 启动独立 Chrome 获取，不复用用户浏览器凭据。
