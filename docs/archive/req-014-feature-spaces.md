# REQ-014 独立功能与交互承接空间

日期：2026-11-02。状态：本批跨端实现与集成验收完成。当前行为以源码、架构规范及运行实例自动生成的 API 文档为准；本记录不替代接口契约。

## 交付范围

- 新闻与短信各自保留内部 Space、原始内容、偏好和处理记录，没有独立用户聊天窗口。首次绑定稳定的 `local-main`，不绑定永久 sessionId，也不跟随当前选中空间。
- 侧栏「功能」管理新闻、短信及其承接空间；显式改绑只接受已存在的普通空间，不迁移数据或移动聊天历史。绑定目标须先改绑再删除，重置保留绑定。
- 新闻保留阅读页，文章可带到绑定空间讨论；服务端读取原文，落盘后返回真实目标，不自动替用户发问或调用模型。新闻明确偏好与 RSS 来源归功能管理。
- 短信默认关闭。Android 授权后在连接根层监听，切页面/空间不卸载；分段长短信先拼接原文，再以稳定来源键接入。重要结果带结构化来源进入承接聊天，静默内容不进入聊天。
- 来源由服务端通知 marker 写入历史与模型上下文，不从正文猜测。受限 `feature` 工具只能沿当前会话实际来源读取原文、保存明确反应与评论，不授予任意跨空间文件、规则或全局记忆写权限。
- 条目反馈归原功能，气泡反馈按真实消息关联进入功能后续处理；撤销/修改读取当前投影。改绑后旧消息仍保留来源，reset 清除聊天反馈与关联，保留功能自身数据。
- 结果未明不自动重发。讨论先进入承接会话核对，用户明确确认并成功回读后恢复操作；功能设置和短信管理提供显式回读入口。

- 服务端 `pnpm check`：typecheck、672 项单元/集成测试、39 项 E2E、生产 Web 构建及差异检查通过。本地夹具测试与以下真实后端/模型证据分开记录，不把前者称为真实模型测试。
- 移动端 lint、typecheck、657 项测试通过；最终 Android JS/资源导出成功。原生隔离 debug APK 使用 x86_64 构建、安装并运行，通过短信本地模块自动链接和编译，不使用正式签名、不修改版本、不覆盖正式应用。
- 主 Agent 从当前服务端源码启动隔离实例，实际调用受保护配置中的外部模型。短信快递提醒与营销静默、默认 main 投递、显式改绑研究空间投递、未绑定聊天不变均通过。绑定恢复 main。
- 真实模型从 main 使用 `feature read/feedback`，短信反应与评论实际保存回原功能；气泡反馈及条目反馈都进入下一轮真实模型输入，下一轮结构化提交成功。
- 真实公网 RSS 抓取并由外部模型筛选新闻；默认承接、改绑、绑定目标删除拒绝、重置后新会话投递及来源持久化通过。隔离环境 DNS 使用 Fake-IP，验收实例显式允许私网目标以访问该公网来源；未修改生产配置或默认 SSRF 防护。
- Android API 36 原生实测：授权短信权限后离开设置、切到其他空间，经模拟器真实电话通道注入长短信，独立短信条目完整保留原文，真实模型通知 main，当前研究会话 revision 不变。
- Android 原生实测新闻功能改绑/恢复、偏好保存与后端回读；从研究空间进入新闻并带到 main；在原生聊天提交明确反馈，由真实模型将 dislike 与评论保存回对应新闻条目。
- 当前 `/docs` 经浏览器实际渲染并截图，功能 API 可见且无页面错误；Web DEV 实测 Feature 工具卡、拒绝错误态与历史刷新。隔离实例显式将 Feature 工具展示设为 summary，不修改用户全局工具配置。
- 中英文手册与移动端 README 同步，文档站构建通过。截图发现来源小字误用了用户气泡白字，已改为共享次级文字语义色，重新执行移动端门禁并在原生核对。

## 首次失败与修正

- 真实供应商对工具 action 的 `anyOf/const` 分支约束异常，导致反复选择 overview；改为 pi SDK 的 provider-compatible `StringEnum`，真实 read/feedback 复测通过。
- 原生长短信最初逐 PDU 上报，同来源键碰撞使后半段丢失；改为同意图按发件人与时间拼接后单次发送事件，重新构建安装并用新的完整长短信复测通过。
- 并发原生构建负载下首次门禁出现两项定时等待失败，未放宽测试；限制 Gradle worker 后完整重跑通过。Web SSE 页面使用 network-idle 等待超时，改为等待文档与实际内容后完成刷新验收，不修改产品代码绕过。

## 后续调整：单一设置入口

用户要求侧栏不展开功能导航。本次将侧栏「功能」与「全局设置」合为一个「设置」入口；新闻和短信直接列入设置首页的「功能」分组，删除多余的功能总览层，不改变 Muse 外观、独立存储或承接空间绑定。

- RSS 从新闻设置进入后，页面返回与 Android 系统 Back 都按「RSS → 新闻设置 → 设置首页 → 聊天」逐层返回，不跳转新闻阅读主页面。设置中的 RSS 同样激活连接内新闻 store，冷启动无需先打开阅读页即可读取真实来源。
- 移动端 lint、typecheck 和 658 项本地测试通过；相关原生脚本入口及配对中英文手册同步，Python 语法检查、文档构建与两端差异检查通过。
- Android API 36 的隔离原生应用通过当前 Metro 加载源码，实测唯一侧栏入口、新闻/短信设置、首次进入 RSS 读取既有真实来源、页面返回和系统 Back。原生聊天提交合成标记后进入设置，真实外部模型完成回复，服务端权威历史同时保留用户请求与助手结果；新闻/短信绑定仍为 main。
- 当前隔离后端的 `/docs` 经浏览器实际渲染，功能 API 可见，无页面错误。服务端业务源码未改，本轮不重复上一批短信处理及改绑全量验收，不声明 iOS、正式 APK 或发布完成。
- 首次原生驱动在未滚动的页面查找屏幕下方的 RSS 来源而超时；补充实际滚动后复测通过，不以修改产品列表或伪造来源绕过。启动时一次 UI 自动化树为空由驱动重新读取恢复。
