# REQ-016 成员式导航与独立私聊首批验收

日期：2026-11-02。服务端与移动端分别在独立 `member-chat` 分支及 worktree 开发；本记录不代表发布，也不代表整个 REQ-016 已完成。

## 本批范围

- 既有 Space 只读投影成成员目录，不新增联系人存储，不迁移真实数据。
- 消息、新闻、成员成为底部主入口；消息行进入私聊，头像先进入成员主页，成员页点击行也进入主页。移除旧空间抽屉及边缘滑动切换。
- 成员主页收敛发消息、文件、规则、技能、会话管理与动态；新闻和短信各自拥有功能设置，全局设置从列表顶部进入。
- 新闻和短信支持独立私聊，规则、文件、会话上下文仍归对应 Space；后台通知绑定默认 main，可改为已建立普通空间，不随当前私聊变化。
- 打开成员目录或私聊不自动启用短信后台处理，也不申请系统短信权限；文件保存继续完整预览、人工确认。

- 当前移动端 lint、typecheck 与 661 项测试通过；中英文手册构建通过。
- 独立数据目录中的当前源码后端真实调用外部模型：短信私聊在后台关闭时查询自己的短信；新闻私聊无短信上下文；main 通过既有空间通信请求短信成员处理并收到结果，短信原私聊历史不被独立讨论追加。
- 运行时 `/docs` 由隔离 Chrome 实际渲染，成员目录端点可见，保留 DOM 与截图证据。未使用用户浏览器资料。
- Android API 36 模拟器运行独立原生 debug 包，完成成员主页、功能设置返回、真实私聊发送与回复、跨成员草稿隔离和返回恢复、动态面板及全局设置分离检查。

## 后续修正：聊天右上角统一为空间设置

同日按用户反馈纠正上一批的顶栏入口：右上角不应是动态面板或新闻阅读，而应始终是当前 Space 的设置。

- Muse、新闻、短信及普通成员私聊统一显示齿轮，进入标明当前成员的「空间设置」；文件、专属规则、技能、会话管理及成员专属功能共用已有领域状态，不新增配置副本。
- 头像仍进入「成员主页」，主页保留发消息，新闻主页保留阅读入口。空间设置不放发消息或新闻阅读按钮；新闻阅读器返回新闻主页，再按主页来源返回私聊或列表。移除失效的阅读器聊天来源分支。
- 功能设置从空间设置进入时明确「返回空间设置」，从主页进入时仍返回主页；子页往返不改变当前 Space。全局连接、主题等设置仍只从会话列表顶部进入。
- 当前移动端 lint、typecheck 与 664 项回归全部通过；中英文手册构建、六个变更页面的本地链接与配对锚点检查通过。最初回归有一个旧动态按钮选择器断言失败，按新入口更新后完整重跑通过。
- 重新启动当前源码隔离后端并实际渲染运行时 `/docs`，保留成员目录端点的 DOM 检查与截图。服务端仅修改文档，不重复与本轮无关的服务端全量业务门禁。
- Android 原生核对三个成员的空间设置归属、头像主页、规则子页返回、新闻和短信功能设置返回、新闻主页阅读及来源子页返回、全局设置分离、聊天草稿保持与跨空间隔离，以及设置页前后台恢复和动态面板入口。
- Android 从短信空间设置返回私聊后只发送一次本轮真实请求，收到真实外部模型回复；HTTP 权威历史确认用户消息与回复仅在短信私聊各一条，main 与新闻均没有该标记。代理记录本轮仅一次外部模型调用并正常结束；短信后台仍关闭，系统 READ_SMS 和 RECEIVE_SMS 均未授予。

本轮证据位于工作区 `ui-previews/space-settings/`：移动端门禁日志、`native-navigation-results.json`、`native-model-results.json`、`live-facts.json`、`model-traces.json`、`docs-render.json`、`manual-docs-check.json` 与原生截图。沿用隔离原生 debug 包加载当前 Metro JS，没有重新构建发行 APK、push 或发布。真实新闻文章详情及 iOS 不在本轮验收范围。
