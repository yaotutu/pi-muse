# REQ-015 空间导航与文件编辑

状态：已实现并通过本批验收。功能模块的交互承接改绑另见 REQ-014，本批不实现。

## 已确认的产品边界

- 日常操作归属当前空间。底部最右侧“设置”改为“空间”；聊天、新闻入口与隐藏目标入口的现状保留。
- 空间使用固定全屏页面，不再寄居头像面板或 Bottom Sheet。二级页同样全屏，统一标题和返回；内容滚动不改变页面高度。
- 头像保留 Muse 交互及动态、审批、执行历史；“历史”不是另一份聊天列表。文件、规则、技能及空间维护归入空间页面。
- 全局设置放在左侧空间抽屉，管理连接、浏览器、更新、全局资料、长期记忆、Dream 和本机主题。空间重置/删除移出全局设置。
- 保留获认可的 Muse 视觉基准和三主题，不再改配色，不引入导航框架，不改另一个 worktree 或浏览器业务。

## 空间页面层级

1. 首页显示当前空间归属，入口为文件、空间规则、空间技能、信息处理及空间维护。
2. 文件：当前空间根目录，逐级进入/返回目录；文件阅读、源码编辑、保存确认分别展示，不把全文堆在目录下。
3. 空间规则：独立阅读和源码编辑，保存后下一轮生效。
4. 空间技能：独立列表，启停只修改当前空间覆盖值，不修改全局技能资产。
5. 信息处理：既有设置归入独立页面，仅调整入口，不冒充短信 Feature 架构改造。
6. 空间维护：重置沿用风险确认；删除明确确认且主空间不可删除。

## 文件与持久化契约

- 文件页面只请求 `scope=space` 和当前 `spaceId`，无共享/其他空间选择器；不删除后端共享能力。
- 文件根在 `workspace/threads/<spaceId>/`。规则实际在 `sessions/<spaceId>/INSTRUCTIONS.md`，使用规则 API，不制造第二份规则文件。技能使用专用 API。
- Markdown 提供安全原生阅读与原文编辑，其他普通 UTF-8 文本也可编辑；不执行 HTML、不自动请求图片，链接只允许安全 HTTP(S)。文件不使用聊天的 `<think>` 清理。
- 手动文件保存展示完整保存前/后内容并人工确认，写回原文件，最后一次成功生效；不做 CAS、自动合并或版本历史。
- 失败保草稿；结果未明先完整回读，不自动重发。模型文件修改仍须版本绑定、完整差异和人工审批。
- 保留后端安全限制：禁止越界、绝对路径及符号链接；目录最多 1000 项，读取最多 8 MiB，文本保存最多 100000 UTF-8 字节，规则最多 20000 字符。历史非 ASCII 名可读，但写入仍使用严格 ASCII 路径校验。
- 不提供独立目录创建/删除入口；文本新建仍可按既有 API 创建缺失父目录。不做文件上传、存储迁移或全局技能源码编辑。

## 导航与草稿

- 根层统一 Android Back：键盘、浏览器、会话面板、侧栏优先；随后处理文件确认/编辑/详情/目录和空间子页，空间首页回聊天。
- 离开编辑保留草稿或明确丢弃；返回目录保留路径与滚动位置。切空间前处理未保存文件，不把旧空间文件草稿标成新空间。
- 规则/技能草稿按空间保留在连接内；不承诺进程重启恢复草稿。
- 保持聊天所有者和 SSE 挂载，不因导航取消运行。空间二级页隐藏底部导航。

2. 实现空间首页及规则/技能/信息处理二级页，调整底部、抽屉和头像职责，保护草稿与返回。
3. 同步本轮回归测试及中英文手册、移动开发/主题指南。
4. 运行移动端 lint、typecheck、test；本地夹具结果与真实验收分开报告。
5. 当前源码隔离后端：核对 health/OpenAPI，浏览器实际渲染 `/docs` 并截图；真实 API 与外部模型验证编辑内容可被消费。
6. Android 原生验证导航、目录、Markdown、原文编辑、完整确认保存、返回/草稿、切空间、键盘及全局设置入口，保留新截图。缺少必要项仅标“实现待验收”。

## 后续 Feature 任务

新闻、短信等使用独立 Feature Space 保存数据，默认 main Space 承接交互，未来可显式改绑到其他 Space；不绑定固定 sessionId，不随当前界面空间切换，也不随改绑迁移数据。新闻保留阅读区域，讨论带来源进入承接会话；短信后台处理，带来源输出并回路反馈。本批记录关系，不提前增加改绑字段或重写通信；详细待决项以 [REQ-014 方案](../discussions/feature-spaces-and-main.md) 为准。
