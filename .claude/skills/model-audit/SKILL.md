# 模型可用性巡检

模型可用状态是高频变化的数据（额度滚动恢复、凭据过期、新供应商上线），本文档区由本技能维护，人工不直接编辑快照表。判定原则：**目录存在 ≠ 可用，配置 ready ≠ 可用，只有真实请求成功才算可用**。

## 流程

1. 运行巡检脚本（在仓库根目录）：

   ```sh
   node scripts/model-audit.mjs --json > /tmp/model-audit.json
   ```

   - 默认抽样模式：每个供应商 1 个代表模型，约 5 次真实调用，额度开销可忽略。
   - 用户要求"全量/逐个"时改用 `--full`（目录内全部模型，32 次调用，先向用户确认再跑）。
   - 退出码 2 = Magpie 网关不可达：先确认 App 在运行（`lsof -i :3425`），网关没启动不算模型不可用，如实报告并停止，不猜测状态。

2. 读取 JSON，按 `results[].status` 归类：`OK` 可用；`LIMIT` 额度触顶（记录 `note` 中的恢复时间）；`AUTH` 凭据失效/未激活（需用户在 Magpie 处理，技能不碰凭据）；`UPSTREAM` 上游故障（可稍后重试一次再定性）；`ERROR` 其他（附 note）。

3. 更新 `docs/model-availability.md`：重写「当前快照」表（日期、每供应商 目录数/实测状态/证据摘要），保留「历史」区追加一行本次结论。只写实测事实，不写未验证的期望。

4. 同步引用它的规则文档（仅当结论变化）：
   - `docs/agent-workflow-guide.md`「执行者与模型路由」的 Magpie 供应商实测表；
   - 服务端 `AGENTS.md` 与移动端 `AGENTS.md` 的委派现状句中的可用性摘要。
   同步的是"当前哪些可用"这一事实层，不改动路由纪律本身。

5. 本地 commit（按已验收模块长期授权，仅纳入本任务文件），不 push、不 bump 版本。交付时给出：本次实测清单、与上次快照的差异（哪些恢复/哪些新坏/新增供应商首次结果）、需要用户动手的事项（如 AUTH 类）。

## 边界

- 凭据与额度管理都在 Magpie App 内完成，属于用户操作；本技能只探测和记录，绝不读取 `~/.cache/magpie` 下的任何凭据文件内容，不在交付中复述错误信息里的 URL。
- 真实调用产生的费用属于已授权的模型测试范围；抽样模式默认执行，全量模式先确认。
- 巡检结果有效期以快照日期为准；超过 7 天的快照用于决策前应先重跑。
